# mxBackup

`mxBackup` — бесплатный пакет резервного копирования для MODX Revolution 2. Он
создаёт архив файлов сайта и SQL-дамп базы данных из CLI, cron или manager,
сохраняет manifest и историю запусков.

- [Страница пакета на modstore](https://modstore.pro/packages/utilities/mxbackup)
- [Релизы на GitHub](https://github.com/ShevArtV/mxbackup/releases)

Пакет поддерживает два готовых профиля:

- `prod` — полная аварийная копия без изменения данных;
- `dev` — обезличенная копия для разработки: сессии удаляются, персональные
  данные MODX и miniShop2 заменяются стабильными тестовыми значениями.

Требования: MODX 2.6–2.8, PHP 7.4+, MySQL/MariaDB и PDO MySQL. Для ZIP нужен
`ext-zip`, для `tar.gz` — `Phar` и `zlib`. Для AES-256 нужен `ext-zip`,
собранный с libzip 1.2 или новее.

## Установка

Скачайте transport из [GitHub Releases](https://github.com/ShevArtV/mxbackup/releases)
или установите пакет через modstore, затем запустите установку в MODX через
«Пакеты → Установщик». После установки
в меню «Пакеты» появится mxBackup, а в каталоге конфигураций будут созданы
файловые профили `prod` и `dev`.

По умолчанию архивы сохраняются в каталоге `backups` рядом с webroot. Путь
внутри webroot, `core`, кэша или корня файловой системы отклоняется до запуска.

## Управление в MODX

В CMP mxBackup настройки разделены по задачам, без редактирования JSON:

- «Профили» — режим `prod`/`dev`, формат архива, AES-256 шифрование ZIP и
  include/exclude для файлов;
- «Таблицы БД» — явное включение и исключение реальных таблиц сайта для каждого
  профиля, с поиском по любой части имени, числом строк, размером и серверной
  пагинацией. «Включить все» и «Исключить все» применяются только к результатам
  текущего поиска; с пустым поиском — ко всем таблицам;
- «Обезличивание» — выбор таблицы и действия для каждого её столбца: маска,
  скрытие, хеш или фиксированная замена; встроенные правила видны отдельно от
  пользовательских, а содержимое служебной таблицы можно полностью очистить;
- «История» — тип запуска, локализованный статус, архив, размер и длительность;
  двойной клик или контекстное меню открывают подробный отчёт. Dry-run до
  создания архива показывает состав таблиц, число обезличиваемых столбцов и
  таблицы, которые будут очищены. Для успешного backup контекстное меню также
  предлагает восстановление после обязательного preflight и ввода кода
  подтверждения. Доступ управляется отдельным правом `mxbackup_restore`.

В профиле `dev` стандартное обезличивание обязательно и не может быть отключено.
Пользовательские правила имеют приоритет над встроенными.

## CLI и cron

```bash
php core/components/mxbackup/cli/mxbackup.php validate-config
php core/components/mxbackup/cli/mxbackup.php dry-run --profile=dev
php core/components/mxbackup/cli/mxbackup.php backup --profile=prod
php core/components/mxbackup/cli/mxbackup.php cleanup
php core/components/mxbackup/cli/mxbackup.php restore-check --archive=/absolute/path/backup.zip
php core/components/mxbackup/cli/mxbackup.php restore --archive=/absolute/path/backup.zip --scope=all --confirm=TOKEN
```

Пример cron для ежедневной production-копии в 03:15:

```cron
15 3 * * * /usr/bin/php /path/to/site/core/components/mxbackup/cli/mxbackup.php backup --profile=prod --no-mail
```

Доступные параметры: `--profile`, `--storage-path`, `--config`,
`--format=tar.gz|zip`, `--mail-to`, `--no-mail`, `--verbose`. Для восстановления:
`--archive`, `--scope=all|files|database`, `--checksum`, `--confirm` и
`--password-file`. Пароль AES-256 также можно передать через переменную окружения
`MXBACKUP_ARCHIVE_PASSWORD`; в аргументе командной строки пароль не принимается.

Профили и пользовательские правила хранятся отдельными PHP-файлами. Каталог
задаётся системной настройкой `mxbackup.config_dir`; значение по умолчанию —
`{core_path}config/mxbackup/profiles/`. Файлы `prod.php`, `dev.php` и собственные
профили можно копировать между сайтами, после чего следует выполнить
`validate-config` и dry-run.

В БД пакет хранит только историю запусков (`mxbackup_run`). Глобальные параметры
архива, почты и retention остаются системными настройками MODX.

Приоритет конфигурации: CLI → общий PHP-файл дополнительных настроек → файловый
профиль → системные настройки MODX → встроенные значения. Пример общего файла:
[`config.example.php`](core/components/mxbackup/docs/config.example.php).

## Безопасность dev-копий

Стандартное маскирование покрывает пользователей и профили MODX, сессии,
заказы, адреса и клиентские профили miniShop2, а также типовые поля `email`,
`phone`, `password`, `token`, `secret` и `api_key`. Маскирование детерминировано:
связанные тестовые записи остаются узнаваемыми между таблицами.

Dev-режим работает по принципу fail-closed: если схема известной чувствительной
таблицы изменилась и обязательные поля невозможно обработать, архив не создаётся.
Для собственных таблиц добавьте правила в manager и сначала выполните dry-run.

Production-архив может содержать пароли и API-ключи из конфигурации сайта. Не
размещайте каталог хранения в публичной части сайта и ограничьте права доступа.
Email по умолчанию выключен; большие архивы к письму не прикладываются.

Для шифрования выберите формат ZIP, включите AES-256 в профиле и задайте пароль.
Пустое поле пароля при повторном редактировании сохраняет прежнее значение.
Пароль хранится в PHP-файле профиля с режимом `0640`, не возвращается в ответы
CMP и не попадает в manifest, историю или логи. Сохраните пароль отдельно:
mxBackup не может восстановить забытый пароль. Шифруется содержимое каждого
элемента ZIP, но имена файлов остаются видимыми; для распаковки нужен архиватор
с поддержкой WinZip AES-256.

## Восстановление

Сначала выполните `restore-check`: команда проверяет тип и checksum архива,
manifest, checksum `database.sql`, все внутренние пути и основную версию MODX.
В ответе будет короткий код `confirmation`. Только после этого запустите
`restore` с тем же архивом и `--confirm=КОД`.

Перед любым изменением mxBackup автоматически создаёт незамаскированный
страховочный backup текущего сайта по production-профилю. Если он не создан,
восстановление не начинается. Файлы сначала полностью распаковываются во
временный каталог, а затем заменяются по одному через atomic rename. Режим
файлов — `merge`: файлы из архива восстанавливаются, но дополнительные файлы
текущего сайта не удаляются. База восстанавливает только таблицы, присутствующие
в dump.

Восстановление изменяет файлы и выполняет `DROP TABLE`; отката одной транзакцией
у MySQL нет. До запуска включите внешний режим обслуживания и остановите cron,
очереди и другие процессы записи. Восстанавливайте только доверенные архивы
mxBackup: checksum защищает от случайной порчи, но не является цифровой подписью.

## Возможности и ограничения

- форматы ZIP и `tar.gz`, опциональное AES-256 шифрование содержимого ZIP;
- include/exclude-правила для файлов и таблиц;
- стандартные и пользовательские правила маскирования, включая JSON path;
- блокировка параллельных запусков, атомарная публикация архива и checksum;
- retention по возрасту и количеству, email-отчёт, история запусков в CMP;
- consistent snapshot для транзакционных таблиц и предупреждения для остальных.
- preflight и восстановление файлов/БД из ZIP, `tar.gz` и AES-256 ZIP;
- автоматический страховочный backup и отдельное право на восстановление.

В текущей версии нет S3/FTP/WebDAV, очереди и автоматического управления внешним
maintenance-режимом.
Большие копии запускайте через CLI/cron: веб-запуск зависит от таймаутов PHP и
reverse proxy.
