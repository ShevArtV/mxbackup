mxBackup 1.0.0-beta
===================

mxBackup создаёт два вида резервных копий сайта MODX:

* prod — аварийная копия файлов и базы данных без изменения данных;
* dev — копия для разработки: сессии удаляются, персональные данные MODX и
  miniShop2 заменяются стабильными тестовыми значениями.

Требования: MODX Revolution 2.6+, PHP 7.4+, MySQL/MariaDB и PDO MySQL.

Быстрый запуск
--------------

    php core/components/mxbackup/cli/mxbackup.php validate-config
    php core/components/mxbackup/cli/mxbackup.php dry-run --profile=dev
    php core/components/mxbackup/cli/mxbackup.php backup --profile=prod

По умолчанию архивы сохраняются рядом с корнем сайта в каталоге backups. Путь
обязан находиться вне webroot; небезопасный путь отклоняется до начала работы.

Приоритет настроек: CLI, core/config/mxbackup.php, профиль из таблиц пакета,
системные настройки MODX, встроенные значения. Пример файла находится в
docs/config.example.php.

Команды CLI
-----------

* backup — создать архив;
* dry-run — показать состав без чтения содержимого и записи архива;
* validate-config — проверить конфигурацию и окружение;
* list-profiles — вывести доступные профили;
* cleanup — применить retention.

Основные параметры: --profile, --storage-path, --config, --format=tar.gz|zip,
--mail-to, --no-mail, --verbose.

Безопасность
------------

Email выключен по умолчанию. Production-архив содержит конфигурацию сайта и
может содержать секреты — храните его только вне webroot. Development-режим
работает fail-closed: если обязательную стандартную маскировку нельзя применить,
архив не публикуется. Всегда проверяйте dry-run после добавления собственных
таблиц с персональными или коммерчески чувствительными данными.

Ограничения первой версии
-------------------------

Нет восстановления, S3/FTP/WebDAV, шифрования, очереди и расписания из CMP.
Большие бэкапы запускайте из CLI/cron: веб-запуск зависит от таймаутов PHP и
reverse proxy.
